# Heuristic Lab

日本語のメタヒューリスティクス可視化サイト。ビルド不要・依存パッケージ不要の静的Webアプリです。

公開サイト: **https://kazu107.github.io/heuristic-lab/**

## GitHub Pagesへの公開

GitHub Actionsの `.github/workflows/pages.yml` が、`main` のサイト・テスト・ワークフローの変更時に検証と公開を行います。28件のテストとJavaScript構文チェックに成功すると、`dist/` をGitHub Pagesに配置します。Actionsタブの **Test and deploy to GitHub Pages → Run workflow** から手動実行もできます。

GitHubの **Settings → Pages → Source** は **GitHub Actions** に設定します。サイトのURLは上記の通りで、ログインなしで閲覧できます。HTML・CSS・ES modulesの参照は相対パスなので、`/heuristic-lab/` のサブディレクトリにも対応しています。Google Fontsの外部通信以外、計算サーバーやAPIキーは不要です。

## 起動

```sh
npm run dev
```

`http://127.0.0.1:4173` を開きます。`dist/` を静的ホスティングに配置するだけでも動きます。Google Fontsが取得できない環境ではシステムフォントで表示します。

## 機能

- 巡回セールスマン、2変数関数最適化、0/1ナップサック、指定色数のグラフ彩色。
- 焼きなまし法、遺伝的アルゴリズム、粒子群最適化、蟻コロニー最適化、差分進化法、山登り法。対応する問題だけ選択可能。
- Rastrigin / Ackley / Rosenbrock / Sphereの4関数と、実際の目的関数によるヒートマップ・等高線。
- 実行・停止・ステップ・速度変更、探索中のパラメーター変更、同じ問題で2手法を比較。
- 収束グラフ、目的関数評価回数、問題サイズ・乱数シード指定、都市のドラッグ編集。
- 最良・現在解の切替、全画面、JSON出力、手法ガイド、設定の端末内保存。
- レスポンシブ表示。狭い画面では右上のボタンで問題・手法を選択。
- ナップサックは10〜10,000個。スライダー・数値入力・プリセットで指定でき、多数の品物は全体を色付きセルで表示。カーソルやタップで個別の価値・重量・選択状態を確認。
- 全問題の反復上限は1〜1,000,000回を数値指定でき、設定を端末内に保存。50倍・100倍・最速モードで長い実験にも対応。
- 関数最適化はシードに応じて地形を回転・平行移動する配置を標準とし、「元の配置」に切替可能。最小値0と既知の最小点を保ち、ヒートマップも実際の変換後の関数を表示。
- グラフ彩色は標準で60頂点・3色、最大150頂点。接続の多さを3段階で選べ、いずれも指定色数の解が存在。
- 関数・彩色は観察向けの手法別初期値と0.5倍速で開始。速度を自分で選んだ後は、問題を切り替えてもその速度を維持。Sphereは入門向けのため速く収束する場合があります。
- 小さい正の目的関数値は指数表記にし、丸め表示で0になって改善が見えなくなることを防ぎます。

## 画面サイズへの対応

レイアウトは `dist/layout.css` で調整しています。メイン領域は画面の全幅を使い、可視化の高さは画面幅と高さに追従します。幅2,200px以上では探索・収束グラフ・設定を横に配置し、1,024px未満では問題・手法の選択をドロワーへ、設定を下段へ移動します。650px以下では1列になります。ヘッダーとデスクトップの選択パネルはスクロール中も操作できます。

320×568から3,840×2,160まで、横向きスマートフォンと各ブレークポイント前後を含む21サイズで表示を確認しています。

## 計算上の定義

全手法の内部スコアは最小化です。ナップサックだけ価値の負数を使い、表示時に正数に戻します。ナップサックは重量超過をランダムに品物を取り除いて修復します。グラフは指定色数で彩色可能な k 部グラフとして生成します。巡回路は無単位の正規化座標によるユークリッド距離です。

関数の変化あり配置は `base(R(−angle) × ((x,y)−offset))` として評価し、変換情報も結果に保存します。彩色の接続率は植え込んだ異色グループ間の辺候補に対して0.22 / 0.42 / 0.62で、全頂点対に対する密度とは異なります。観察向け調整は問題の構造と公開パラメーターによるもので、最良値の表示を遅らせたり解の発見を保留したりしません。収束速度は関数・手法・シードで変わります。

比較には同じ問題・同じシードを使いますが、1反復の目的関数評価回数は手法によって異なります。グラフの横軸は反復回数です。厳密な性能ベンチマークや最適性証明ではありません。変更後のパラメーターは次のステップに反映されます。比較側はその手法の既定パラメーターを使います。

SAはMetropolis受理と指数冷却、GAはトーナメント選択・エリート保存（TSP:順序交叉、連続:ブレンド交叉、離散:一様交叉）、PSOは慣性重みと自己・群れの最良位置、ACOはAnt System、DEはDE/rand/1/binです。山登り法は比較用の局所探索です。

## 検証

```sh
npm test
```

対応する全15組合せの解の有効性、目的値の整合、最良値の単調性、シード再現性、既知最小点への収束、評価回数、実行中の個体数変更を検証します。

JSON出力には問題データ・設定・最良解・収束履歴が入ります。履歴は最大2400点に間引きながら、初期点・最新点と実験全体を通したサンプルを残します。`historySampleStride` は間引き間隔です。実行中に設定を変えた場合は、その変更履歴自体は保存しません。

追加の検証では10,000個で3手法の容量制約・価値を確認し、1,000,000反復でも履歴が上限内で序盤・中盤・終盤を保持すること、小画面から大画面まで全セルが描画範囲に収まり詳細の位置判定が一致することを確認します。
